Локальный агент для домашнего инвентаря¶

Исследуем, может ли qwen3:4b-instruct самостоятельно выбирать инструменты, вести диалог и безопасно изменять небольшое внешнее хранилище. Все вещи и пользовательские запросы в работе синтетические.

Сначала проверим минимальную инструкцию, затем улучшим её по ошибкам на разработочной части сценариев. Отдельные контрольные сценарии не используем при подборе инструкции. Дополнительно исследуем повторяемость, память во внешнем хранилище и перенос вещей между местами хранения.

2. Предметная область и хранилище¶

Одна позиция — вещь в определённом месте: item_id, name, location, quantity, unit. Название, место и единица измерения образуют уникальный ключ; одинаковая вещь может находиться в разных местах. Количество — целое неотрицательное число; ноль не удаляет запись автоматически.

Один документ MongoDB содержит positions, журнал movements, счётчики ID и version. Каждый независимый опыт получает собственный _id. Замена по условию текущей версии защищает от записи поверх устаревшего состояния. Перенос изменяет обе позиции и журнал одной атомарной заменой документа. Для небольшого учебного инвентаря это удобно; масштабирование рассмотрим в ограничениях. Демонстрационная база и чужие записи не затрагиваются.

def commit_inventory(root, expected_version):
    if root["version"] != expected_version:
        raise ToolError("VERSION_CONFLICT", "Состояние изменилось; повторите чтение")
    root["version"] += 1
    result = collection.replace_one({"_id": root["_id"], "version": expected_version}, root)
    if result.matched_count != 1:
        raise ToolError("VERSION_CONFLICT", "Конкурирующая запись; повторите чтение")
    return root["version"]

def add_item(scope, name, location, quantity, unit, expected_version):
    root = load_inventory(scope)
    candidate = {"name": name, "location": location, "quantity": quantity, "unit": unit}
    if any(position_key(item) == position_key(candidate) for item in root["positions"]):
        raise ToolError("ALREADY_EXISTS", "Такая позиция уже есть; новая запись не создана")
    candidate["item_id"] = f"I{root['next_item_id']:03d}"
    root["next_item_id"] += 1
    root["positions"].append(candidate)
    version = commit_inventory(root, expected_version)
    return {"ok": True, "version": version, "item": candidate}

def delete_item(scope, item_id, expected_version):
    root = load_inventory(scope)
    removed = get_item(root, item_id)
    root["positions"] = [item for item in root["positions"] if item["item_id"] != item_id]
    version = commit_inventory(root, expected_version)
    return {"ok": True, "version": version, "removed": removed}

def dispatch_tool(scope, name, arguments, fault):
    try:
        if name not in HANDLERS or name not in fault.get("_allowed_tools", HANDLERS):
            raise ToolError("UNKNOWN_TOOL", "Неизвестный инструмент")
        if isinstance(arguments, str):
            arguments = json.loads(arguments)
        args = ARG_MODELS[name].model_validate(arguments).model_dump()
        if name in READ_TOOLS and fault.get("fail_first_read", False):
            fault["fail_first_read"] = False
            raise ToolError("TEMPORARY_UNAVAILABLE", "Временный сбой чтения. Повторите запрос", True)
        if fault.get("_guarded"):
            validate_tool_context(name, args, fault)
        result = HANDLERS[name](scope, **args)
        if fault.get("_guarded"):
            fault["_read_version"] = result["version"] if name in READ_TOOLS else None
        return result
    except ValidationError as exc:
        return fail_result("INVALID_ARGUMENTS", json.dumps(exc.errors(include_url=False), default=str))
    except (ValueError, TypeError) as exc:
        return fail_result("INVALID_ARGUMENTS", str(exc))
    except ToolError as exc:
        return fail_result(exc.code, exc.message, exc.retryable)
    except PyMongoError:
        return fail_result("STORAGE_ERROR", "Хранилище недоступно; результат записи требует проверки")

В каждом шаге сохраняются вход модели, исходный ответ, вызовы инструментов, аргументы, результаты и снимки MongoDB. Ограничены число раундов и вызовов; исчерпание бюджета — отдельный исход, а не выдуманный успешный ответ.

Кэш хранит сырые ответы модели по хэшу запроса и digest модели. При повторном запуске ноутбука инструменты исполняются заново на тех же учебных фикстурах: это восстанавливает состояние и проверяет воспроизводимость. Поведение модели после ошибки не заменяется эталонной последовательностью действий.

def call_model(messages, descriptions, options):
    payload = {"model": MODEL, "messages": messages, "tools": tool_specs(descriptions),
               "stream": False, "keep_alive": "30m", "options": options}
    identity = json.dumps({"digest": MODEL_DIGEST, "payload": payload}, ensure_ascii=False, sort_keys=True)
    key = hashlib.sha256(identity.encode()).hexdigest()
    path = CACHE / f"{key}.json"
    if USE_CACHE and path.exists():
        return json.loads(path.read_text()), True
    started = time.perf_counter()
    response = requests.post(f"{OLLAMA_URL}/api/chat", json=payload, timeout=600)
    response.raise_for_status()
    record = {"key": key, "request": payload, "response": response.json(),
              "wall_s": time.perf_counter() - started, "model_digest": MODEL_DIGEST}
    path.write_text(json.dumps(record, ensure_ascii=False, indent=2))
    return record, False

def execute_calls(scope, calls, history, trace, fault):
    for call in calls:
        name = call.get("function", {}).get("name", "")
        arguments = call.get("function", {}).get("arguments", {})
        before = load_inventory(scope)
        started = time.perf_counter()
        result = dispatch_tool(scope, name, arguments, fault)
        elapsed = time.perf_counter() - started
        trace.append({"tool": name, "arguments": arguments, "result": result,
                      "before": before, "after": load_inventory(scope), "wall_s": elapsed})
        history.append({"role": "tool", "tool_name": name,
                        "content": json.dumps(result, ensure_ascii=False)})

def agent_turn(scope, user_text, prompt, descriptions, options=None, history=None, fault=None, guarded=False):
    history = copy.deepcopy(history) if history else [{"role": "system", "content": prompt}]
    history.append({"role": "user", "content": user_text})
    trace, generations = [], []
    fault = dict(fault or {})
    fault.update({"_guarded": guarded, "_user_text": user_text, "_allowed_tools": list(descriptions)})
    options = dict(options or OPTIONS)
    status, answer = "budget_exhausted", ""
    for step in range(MAX_ROUNDS):
        record, cached = call_model(history, descriptions, options)
        generations.append({"key": record["key"], "wall_s": record["wall_s"],
                            "cached": cached, "response": record["response"]})
        message = record["response"]["message"]
        history.append(message)
        calls = message.get("tool_calls", [])
        if not calls:
            answer, status = message.get("content", ""), "finished"
            break
        if step == MAX_ROUNDS - 1 or len(trace) + len(calls) > MAX_TOOL_CALLS:
            break
        execute_calls(scope, calls, history, trace, fault)
    return {"status": status, "answer": answer, "history": history,
            "trace": trace, "generations": generations, "final_state": load_inventory(scope)}

Один вызов инструмента не завершает диалог: ответ инструмента возвращается модели, и она решает, нужен ли следующий шаг или ответ пользователю. Несколько вызовов в одном сообщении выполняются последовательно. Ошибки возвращаются тем же каналом; инструмент не изменяет данные при неверных аргументах.

def run_metrics(run):

def parse_creation_quotes(args, text):
    quantity_quote, unit_quote = args["quantity_text"], args["unit_text"]
    present = bool(quantity_quote) and re.search(r"(?<![\w+.-])" + re.escape(normalize(quantity_quote)) + r"(?![\w.,])", normalize(text))
    numbers = re.findall(r"(?<!\w)[+-]?\d+(?!\w)", quantity_quote)
    units = [unit for unit, pattern in UNIT_PATTERNS.items() if re.search(pattern, normalize(unit_quote))]
    if not present or not quote_present(unit_quote, text) or len(numbers) != 1 or len(units) != 1:
        raise ToolError("EVIDENCE_REQUIRED", "Уточните цифровое количество и единицу; цитаты должны быть в текущем сообщении")
    quantity = int(numbers[0])
    if not 1 <= quantity <= MAX_QUANTITY:
        raise ToolError("INVALID_QUANTITY", f"Количество новой позиции должно быть от 1 до {MAX_QUANTITY}")
    return {"quantity": quantity, "unit": units[0]}

def search_items(scope, query="", location=""):
    root = load_inventory(scope)
    by_id = bool(re.fullmatch(r"I[0-9]{3,}", query))
    items = [item for item in root["positions"]
             if (item["item_id"] == query if by_id else words_match(query, item["name"]))
             and (not location or words_match(location, item["location"]))]

9. Как оцениваем надёжность¶

Автоматически проверяем состояние, успешные изменения без разрешения, валидность вызовов, завершение цикла и чтение перед записью. Дополнительно просматриваем все ответы и трассы: понял ли агент намерение, уточнил ли нужные поля, выбрал ли подходящий инструмент, взял ли аргументы из запроса или хранилища, корректно ли объяснил ошибку и подтверждён ли ответ результатом.

Содержательную проверку выполнил Codex по сохранённым диалогам; независимой человеческой экспертизы нет. Применимость уточнения и ошибки отмечается отдельно: отсутствие ошибки не считается доказательством умения её обрабатывать. Разметка результатов хранится отдельно.

10. Расширение: перенос вещей¶

Новый инструмент переносит указанное количество между местами хранения и добавляет запись в журнал движений. Если позиция назначения существует, количество увеличивается; иначе создаётся новая. Общий запас вещи сохраняется. Недостаточный остаток и одинаковые места — ошибки без частичного изменения. Все действия внутри одного документа MongoDB фиксируются атомарно по версии.

def move_stock(scope, source_id, destination_location, quantity, expected_version):
    root = load_inventory(scope)
    source = get_item(root, source_id)
    if normalize(source["location"]) == normalize(destination_location):
        raise ToolError("SAME_LOCATION", "Место назначения совпадает с исходным")
    if source["quantity"] < quantity:
        raise ToolError("INSUFFICIENT_STOCK", f"Недостаточно запаса: доступно {source['quantity']}")
    destination = prepare_destination(root, source, destination_location)
    source["quantity"] -= quantity
    destination["quantity"] += quantity
    movement = {"movement_id": f"M{root['next_movement_id']:03d}", "name": source["name"],
                "from": source["location"], "to": destination["location"], "quantity": quantity,
                "unit": source["unit"], "at": FIXED_TIME}
    root["next_movement_id"] += 1
    root["movements"].append(movement)
    version = commit_inventory(root, expected_version)
    return {"ok": True, "version": version, "source": source, "destination": destination, "movement": movement}

Документация¶

Вызовы инструментов в Ollama определяют формат обмена assistant → tool → assistant. Строгая валидация Pydantic используется для запрета неявного преобразования аргументов. Атомарность MongoDB обосновывает замену одного документа с проверкой ожидаемой версии. Эти свойства инфраструктуры не гарантируют, что модель правильно поняла просьбу. SequenceMatcher в стандартной библиотеке Python используется для сравнения написания слов, а не для понимания смысла.

11. Сводная оценка и сравнение¶

«Задача решена» оценивает итог пользовательской просьбы: правильную операцию, ответ о запасе или необходимое уточнение. Ошибочные промежуточные вызовы и необоснованные побочные фразы проверяются отдельно. «Полный зачёт» — более строгая оценка по перечисленным критериям: весь сценарий выполнен без неправильных вызовов, выдуманных аргументов, необоснованных уточнений и ошибок в ответе. Исправленный после ошибки сценарий может решить задачу, но не получить строгий зачёт. Неприменимые критерии отмечены null, например обработка ошибки там, где ошибки не было. В зависимой цепочке локальное выполнение запроса оценивается по фактическому состоянию, а state_ok — по идеальной цепочке. Поэтому поздний достоверный ответ может быть локально правильным после ошибки предыдущего шага.

Для дополнительных проверок считаем, прочитано ли состояние перед успешной записью и было ли проверочное чтение после неё. Неверное состояние и любое успешное изменение вне разрешённой операции исключают строгий зачёт.

def process_metrics(run):
    observed, write_checks, verification = None, [], []
    for i, row in enumerate(run["trace"]):
        if row["tool"] in READ_TOOLS and row["result"]["ok"]:
            observed = row["result"]["version"]
        elif row["before"] != row["after"]:
            write_checks.append(row["arguments"].get("expected_version") == observed)
            verification.append(any(later["tool"] in READ_TOOLS and later["result"]["ok"]
                                    and later["result"]["version"] >= row["after"]["version"]
                                    for later in run["trace"][i + 1:]))
            observed = None
    errors = Counter(row["result"].get("error", {}).get("code") for row in run["trace"] if not row["result"]["ok"])
    return {"read_before_write": all(write_checks) if write_checks else None,
            "read_after_write": all(verification) if verification else None,
            "invalid_calls": errors["INVALID_ARGUMENTS"] + errors["UNKNOWN_TOOL"],
            "error_codes": dict(errors)}

Для дальнейшего развития прежде всего нужно исправить создание: после чтения пустого результата модель должна продолжать явно запрошенное добавление. Возможный следующий эксперимент — инструмент атомарного создания, который сам проверяет уникальность и текущую версию внутри хранилища. Такой вариант здесь не испытывался.

Проверку результата и разрешённости операции стоит закреплять в коде, а не поручать только текстовой инструкции. Короткие инструменты с недублирующими аргументами уменьшают неоднозначность интерфейса; клиенту также нужен явный черновик незавершённой операции для уточнений и отмены.

12. Ограничения и рекомендации¶

Небольшие синтетические русскоязычные сценарии, пять исходных позиций и одна модель не представляют все бытовые запросы. Контрольных сценариев всего четыре; три повтора при одной температуре не доказывают промышленную надёжность. Результаты зависят от модели, квантизации, шаблона инструментов, формулировок, истории диалога и бюджета шагов. Сравнение V1/V5 включает несколько изменений сразу; вклад каждого отдельно не измерен.

В V5 поиск допускает сходство слов, но это не полноценная морфология или понимание смысла: возможны лишние кандидаты и пропуски. Неверный фильтр всё ещё может скрыть существующую вещь; несколько кандидатов требуют уточнения. Проверка цитат создания поддерживает цифровое количество и небольшой набор единиц. Она не доказывает правильность имени, места или намерения и требует подтверждения количества и единицы в текущей реплике. Словесные числа и заполнение полей по нескольким сообщениям потребуют структурированного черновика с происхождением каждого поля. Защита создания не гарантирует отсутствие ошибочных изменений или удалений.

Один документ MongoDB упрощает атомарный перенос, но ограничен размером 16 MiB, копируется целиком и создаёт общую точку конкуренции. Проверка версии защищает от устаревшей записи, однако нагрузочные и конкурентные испытания не проведены. Время в журнале фиксировано для воспроизводимости, а не является фактическим временем каждой операции. Для продукта нужны отдельные сущности, аудит, контроль доступа и идемпотентные команды. После сетевого сбоя записи её итог может быть неопределённым: нужно сверять состояние, а не слепо повторять запрос.

Отмена в исследовании относится к ещё не выполненному действию. Она не является откатом уже завершённых изменений. Память диалога хранится в Python; внешнее хранилище сохраняет инвентарь. Ограничение цикла предотвращает бесконечную работу, но не гарантирует завершения цели. Проверялся внедрённый сбой одного чтения, полное отключение MongoDB и сбой журналирования не испытывались. Сбой самого HTTP-сервиса модели прерывает выполнение; устойчивое восстановление после него здесь не исследовано.

Для дальнейшего развития стоит хранить явный черновик операции, проверять аргументы и права в коде, требовать подтверждение важных удалений и увеличивать набор независимых тестов. Инструкция помогает модели выбрать действие, но сохранность данных должна обеспечиваться приложением и хранилищем.

13. Воспроизведение и сохранение¶

Запуск окружения: docker compose up --build; Jupyter: http://127.0.0.1:8888/?token=agent. Выполнение всех ячеек сбрасывает только исследовательские фикстуры inventory_v1:* в отдельной базе и заново исполняет инструменты. Кэш исходных ответов находится в agent_results/llm_cache, диалоги и состояния — в JSON, сводная оценка — в evaluation.csv.

Оценки привязаны хэшем к ответу, вызовам и состоянию. Если генерация меняется, содержательную проверку нужно выполнить заново; старые отметки не переносятся. Кэш позволяет проверить результаты без повторной генерации; новые независимые прогоны требуют другого seed или отключения чтения кэша. Результаты таких прогонов могут отличаться. Эталонные позиции и содержательная оценка не передаются модели. Исходное демо сохранено без изменений.

После сохранения ноутбука и HTML контейнеры останавливаются с хоста командой docker compose down. Именованные тома остаются, поэтому модель и учебная база не теряются при остановке.
